# Reproducibility

## Recommended Environment

### R
- R 4.1+ (many cluster scripts assume R 4.0/4.1 modules).
- Use `renv` for package pinning in your local clone.

Bootstrap:
```bash
R -q -e 'install.packages("renv"); renv::init(bare = TRUE)'
```

Suggested core R packages used by entry workflows:
- `tidyverse`, `dplyr`, `ggplot2`, `caret`, `pROC`, `doParallel`
- `DESeq2`, `sva`, `GenomicRanges`, `ComplexHeatmap`

### Python
- Python 3.10+ recommended.
- Install from `requirements.txt`.

## Deterministic Settings
- Python classifiers set `seed = 123` internally.
- Several R scripts call `set.seed(123)` for cohort splitting/model steps.
- Keep seed values unchanged when reproducing manuscript results.

## Reproducibility Checklist
1. Use a clean environment (`renv`/virtualenv).
2. Record exact input file versions and paths.
3. Keep metadata/feature sample ID normalization consistent.
4. Preserve run tables (`run_tab_*.csv`, CN config CSVs) used for execution.
5. Capture software versions:
   - `R -q -e 'sessionInfo()'`
   - `python -V && pip freeze`
6. Save scheduler logs (`.out/.err`) for cluster jobs.

## Validation Steps
- Confirm sample intersections are non-empty after metadata filtering.
- Confirm class counts are sufficient for selected cross-validation folds.
- Confirm expected output files are written after each stage before moving downstream.

## Known Reproducibility Risks
- Many scripts contain absolute cluster paths from original execution environment.
- Some scripts assume pre-existing intermediate objects/files generated by earlier unpublished steps.
- Path edits are often required for external users; document your edits in a run log.
